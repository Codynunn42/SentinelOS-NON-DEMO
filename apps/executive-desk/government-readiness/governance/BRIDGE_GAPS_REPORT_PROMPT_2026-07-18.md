# Bridge Gaps Report Prompt

## Command

PRIVATE: Using my LOGIC.

One moment, Sentinel AI.

Bridge Gaps Report: supply in Dr. Mode.

Ask about FIX and SET logic using my command logic to enact technology education.

Sentinel AI:

Analyze the Bridge Gap Report and use it for remediation and implementation of the next steps in Light Mode.

I want to take the BGP and hook it to North Star and doctrine, then create a technology implementation that bridges the gap.

IN DOCTOR MODE, tell me what is keeping you from a FIX AND SET and this entry.

## Objective

Use the Bridge Gaps Report to identify what is blocking the next governed implementation step, map the gap to North Star and doctrine, and produce a concise remediation path that bridges the gap without mutating runtime state.

## Authority and Boundaries

- Mode: read-only analysis and documentation.
- Runtime mutation: prohibited.
- Deployment: prohibited.
- Azure mutation: prohibited.
- Authentication configuration changes: prohibited.
- Gate weakening or removal: prohibited.
- Doctrine restructuring: prohibited unless separately approved.

Preserve all canonical filenames, inheritance relationships, evidence requirements, and approval boundaries.

## Source Stack

Review and compare:

1. The current Bridge Gaps Report or equivalent GBP traceability/gap report.
2. The Executive Desk gate certification path.
3. The latest gate-certification-report.json.
4. The latest certification summary and gate evidence artifacts.
5. The GBP Chief of Staff Brief.
6. The GBP Operating Runbook.
7. The Executive Review Checklist.
8. The Government Deployment Blueprint and related deployment-profile materials.
9. Applicable Master Operating Blueprint and Executive Desk governance requirements.

## Required Interpretation

Treat the phrase BGP as the Bridge Gaps Problem: the gap between current governed readiness and the next authorized remediation step.

Treat North Star as the outcome-first government mission direction already established in the GBP brief and runbook.

Treat doctrine as the governing constraints and evidence rules already present in the Executive Desk and GBP materials.

Treat FIX and SET as the next governed implementation cycle:

- FIX = identify the minimal controlled correction that closes the current gap.
- SET = define the governed target state and the evidence required to hold it.

## Required Output

Return a concise report with these sections:

1. North Star alignment.
2. Doctrine alignment.
3. Current gap summary.
4. What is keeping us from FIX and SET.
5. Technology implementation recommendation.
6. Evidence still missing.
7. Next governed step in Light Mode.

## Doctor Mode Rules

In Doctor Mode, answer only what is keeping the system from a valid FIX and SET entry.

Your answer must distinguish between:

- positive-path success,
- negative-control coverage,
- profile mapping,
- escalation readiness,
- evidence completeness,
- and deployment authorization.

## Light Mode Rules

In Light Mode, keep the output bounded and action-oriented.

Show:

- what is ready to go,
- what needs focus now,
- what evidence is missing,
- what the minimal remediation is,
- and what the next implementation step should be.

## Output Style

- Start with the government outcome, not the product feature.
- Keep the tone concise, direct, and actionable.
- Tie every claim to evidence or a verified operating state.
- Avoid generic modernization language unless it advances the government outcome.
- Optimize for relationship building, readiness, and next-step clarity.

## Final Rule

Do not claim full certification.

If the gap remains, say so directly and specify the next controlled action required to bridge it.
